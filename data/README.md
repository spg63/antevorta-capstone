# data/

Raw datasets, generated SQLite databases, and full derived exports live here locally and are **never committed** (see
the repo `.gitignore`). What IS committed: `DATA_PROVENANCE.md` (versions, URLs, SHA-256 checksums, row
counts — created by ticket W1-01), compact aggregate manifests under `data/reference_manifests/` (schema,
counts, and hashes only), and small fixture excerpts (which live under `tests/`, not here).

Datasets and the `antevorta-db` reference module are provided by the stakeholder (Dr. Grimes) — ask him, not
Kaggle's search box, if anything is missing.

**This repository is public.** Any committed excerpt (fixtures included) must comply with its source
dataset's license/terms of use: keep excerpts minimal, and record the source + license alongside the
checksums in `DATA_PROVENANCE.md`.

## Hollywood labels

The label is `1` when revenue is strictly greater than twice the budget, and `0`
otherwise, including when revenue equals twice the budget.

After building the database, add or refresh the `label` column in its computed
`movies` table:

```bash
python scripts/label_w1_04_movies.py
```

Run this step after every rebuild of the SQLite database. It updates the database
transactionally; the W1-02 build manifest's database hash describes the feature-only
artifact before this labeling step.

To measure the label balance and compare it with the reference-derived threshold,
run the following after generating `data/processed/movies.sqlite`:

```bash
python scripts/reconcile_w1_04_labels.py --output results/manifests/w1_04_label_reconciliation.json
```

The SQLite input is generated by the W1-03 Python pipeline; it is not an independent
reference database. The comparison corrects the older reference code's exact-5×
fall-through and is therefore not an exact reproduction of its label column.
